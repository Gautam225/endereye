# Project Instructions

## General Rules
- Understand existing code before changing anything.
- Keep changes small and focused on the requested task.
- Do not rewrite working code unnecessarily.
- Never modify unrelated files.
- Do not add dependencies without a clear reason.
- Follow existing project architecture and coding conventions.

## Workflow
1. Identify the relevant files.
2. Inspect only the code needed for the task.
3. Explain the root cause before fixing bugs.
4. Implement the smallest reliable solution.
5. Run relevant tests or validation.
6. Report changed files and test results.

## Token Efficiency
- Avoid reading the entire repository unnecessarily.
- Do not repeatedly read unchanged files.
- Avoid printing entire files or large command outputs.
- Prefer targeted searches and relevant code sections.
- Keep explanations short and practical.
- Do not repeat information already established.
- Ask questions only when missing information blocks progress.

## Safety
- Never expose secrets, API keys, or passwords.
- Never overwrite environment files or user data unnecessarily.
- Never run destructive commands without permission.
- Do not commit, push, or deploy unless explicitly requested.

## Code Quality
- Prefer simple, maintainable solutions.
- Follow existing patterns instead of introducing new architecture.
- Add tests for important changes.
- Report failures honestly; never claim tests passed without running them.
